## 1. 이 앱은 무엇인가요

이미 예약을 마친 여행의 정보를 한곳에 모아두고, 여행 중에 필요한 것만 빠르게 꺼내 보고,
여행이 끝난 뒤에는 두 사람이 각자의 시선으로 같은 하루를 기록하는 앱입니다.

| 화면 | 하는 일 |
| --- | --- |
| **오늘** | 도쿄 · 삿포로 실시간 날씨와 현지 시계, 오늘 날짜·도시, 다음 일정과 남은 시간, 출발 권장 시각, 오늘 쓸 티켓, 숙소, 이동 경로, 자주 쓸 일본어, 오늘의 기록, 긴급 연락처 |
| **일정** | 날짜별 세로 타임라인. 추가·수정·삭제·완료 표시·꼭 가기 표시·짧은 메모 |
| **예약** | 항공 / 숙소 / 관광·투어·공연·경기·열차·음식점 예약, QR·티켓 이미지 |
| **현지** | 회화(152개), 주요 어휘(88개), 노선도·길찾기(도쿄·삿포로), 이동 경로 |
| **기록** | 두 사람의 기록을 한 줄기로 모은 피드(작성자 표시), 사진 · 영상, 지출, 여행 요약 |

그리고 화면 위쪽 **🔍 버튼**(PC 에서는 `Ctrl + K`)을 누르면
일정 · 예약 · 항공 · 숙소 · 회화 · 어휘 · 역 · 경로 · 기록 · 지출을
**한 번에 검색**할 수 있습니다. 결과를 누르면 해당 화면으로 바로 이동합니다.
각 목록(일정 / 예약 / 경로 / 회화 / 어휘)에도 검색창이 따로 있습니다.

기술적으로는 이렇게 되어 있습니다.

* **화면** : 스마트폰에서는 하단 탭바를 쓰는 **앱 형태**, PC 에서는 왼쪽 메뉴를 쓰는 **웹사이트 형태**로 자동 전환
* **아이콘** : Google Material Symbols
* **프런트엔드** : HTML + CSS + JavaScript (빌드 과정 없음) → GitHub Pages 에 그대로 올리면 끝
* **백엔드** : Google Apps Script 웹 앱 (`Code.gs`)
* **데이터베이스** : Google Sheets
* **사진 · 영상 저장소** : Google Drive
* **날씨** : [Open-Meteo](https://open-meteo.com) (API 키가 필요 없는 무료 서비스)
* **설치** : PWA (스마트폰 홈 화면에 앱처럼 설치 가능, 오프라인 열람 지원)

## 1-1. 노선도와 길찾기 (오픈 데이터)

**현지 → 노선 · 길찾기** 에서 도쿄권과 삿포로·홋카이도의 전철 노선을 볼 수 있습니다.

| 도시 | 담긴 내용 |
| --- | --- |
| 도쿄권 | 176개 노선 / 2,576개 역 (도쿄메트로 · 도에이 · JR동일본 · 사철 전반) |
| 삿포로 · 홋카이도 | 6개 노선 / 118개 역 (지하철 3개 노선, 시전, JR 지토세선, JR 하코다테 본선) |

* **길찾기** : 출발역과 도착역을 고르면 환승 경로를 계산합니다.
  탈 노선 · 방면 · 정차역 수 · 환승역이 노선 색과 함께 표시됩니다.
* **노선도** : 노선을 고르면 역 순서를 색 띠와 함께 보여줍니다. 역을 누르면 일본어 역명이 크게 뜹니다.
* 찾은 경로는 **[이동 경로로 저장]** 으로 기존 "이동 경로"에 그대로 넣을 수 있습니다.
* 역 이름은 한국어 · 일본어 · 역 번호(JY01 등) 아무거나로 검색됩니다.

### ⚠️ 이 기능의 한계 (꼭 읽어주세요)

이 앱의 길찾기는 **구글 지도를 대신하지 못합니다.** 아래는 담고 있지 않습니다.

* **시각표** — 첫차 · 막차 · 몇 시 몇 분 열차인지 알 수 없습니다.
* **요금** — 운임 계산이 들어 있지 않습니다.
* **실시간 운행 정보** — 지연 · 운휴를 알 수 없습니다.
* **급행 · 쾌속 구분** — 모든 역에 서는 것으로 계산합니다.

소요 시간은 **역 1개당 2분, 환승 1회당 5분**으로 계산한 **추정치**입니다.
그래서 결과 화면에 **[구글 지도에서 보기]** 버튼을 함께 두었습니다.
정확한 시각·요금은 반드시 구글 지도나 공식 사이트에서 확인해 주세요.

이 기능이 쓸모 있는 상황은 이런 때입니다.
**비행기 안이나 지하에서 인터넷이 안 될 때**, 어느 노선을 타고 어디서 갈아타는지 미리 확인하는 용도.
(노선 자료는 앱에 저장되어 오프라인에서도 동작합니다)

### 자료 출처

| 출처 | 라이선스 | 사용한 부분 |
| --- | --- | --- |
| [nagix/mini-tokyo-3d](https://github.com/nagix/mini-tokyo-3d) | MIT | 도쿄권 노선·역·**한국어 역명**·노선 색·좌표 |
| [piuccio/open-data-jp-railway-stations](https://github.com/piuccio/open-data-jp-railway-stations) | MIT (ekidata 기반) | 역 번호, 삿포로·홋카이도 노선과 역 순서 |

삿포로·홋카이도 역의 한국어 표기는 이 저장소에서 직접 붙였습니다.
자료를 새로 만들려면 `data/transit.js` 를 다시 생성하면 됩니다. (생성 방법은 파일 첫머리 주석 참고)

**버스**는 노선·시각표가 자주 바뀌고 지역마다 제각각이라 이 앱에는 담지 않았습니다.
현지에서는 정류장에 붙은 안내판이나 구글 지도, 공식 버스 회사 사이트를 확인해 주세요.

> 예전 버전에 있던 **"역 정보" · "버스 정보" 탭은 노선도·길찾기로 대체되어 사라졌습니다.**
> 역·버스 정보를 직접 기록해 두고 싶다면 Google Sheets 의 `Stations` / `Buses` 시트에
> 그대로 입력할 수 있습니다 (앱 화면에는 표시되지 않지만 시트에는 계속 저장됩니다).

## 1-2. 화면과 데이터가 이어지는 방식

**기기에 따라 화면이 달라집니다**

| 화면 폭 | 모습 |
| --- | --- |
| 1023px 이하 (스마트폰 · 태블릿) | 하단에 5개 탭바가 있는 **앱 형태**. 오른쪽 아래 + 버튼으로 바로 추가 |
| 1024px 이상 (PC) | 왼쪽에 메뉴가 고정된 **웹사이트 형태**. 목록이 2단으로 넓게 표시 |

> 스마트폰에서 화면이 작게 나온다면 브라우저의 **"데스크톱 사이트"** 설정이 켜져 있는지 확인하세요.
> (크롬 `⋮` → `데스크톱 사이트` 체크 해제)

**날짜를 축으로 모든 것이 연결됩니다**

일정 · 항공 · 숙소 · 예약 · 기록 · 사진 · 지출은 모두 **같은 날짜**로 묶입니다.

* 일정 탭에서 고른 날짜가 기록 탭에서도 그대로 유지됩니다.
* 기록 화면 위쪽의 **"이 날의 일정"** 카드에서 그날의 일정 · 숙소 · 지출을 한눈에 봅니다.
* 기록을 쓸 때 **"이 날 일정을 기록에 불러오기"** 버튼으로 방문한 장소를 자동으로 채웁니다.

**기록은 하나의 피드입니다**

내 기록과 상대방 기록을 나누지 않고 **한 줄기로 모아서** 보여줍니다.
각 카드에 누가 썼는지(이름 · 이모지 · `나` / `파트너` 배지)가 표시됩니다.
예전에 쓴 "공동 기록"도 같은 피드에 `함께 쓴 기록` 으로 나타납니다.

**사진과 파일은 여러 장 붙일 수 있습니다**

사진 · 티켓 · QR · 예약 확인서 항목마다 **여러 장을 한 번에** 선택해 올릴 수 있습니다.
올린 파일은 격자로 보이고, 각각 × 버튼으로 지울 수 있으며,
누르면 좌우로 넘겨보는 전체 화면 뷰어가 열립니다.

## 3. 데이터 흐름

```
[스마트폰 브라우저]
      │  ① 로그인 (여행 코드 + 비밀번호 + 사용자)
      ▼
[Apps Script 웹 앱]  ── 비밀번호를 SHA-256 해시로 비교
      │  ② 세션 토큰 발급 (Sessions 시트에 저장)
      ▼
[브라우저 localStorage] 토큰 저장 → 다음부터 자동 로그인
      │
      │  ③ 모든 데이터 요청에 토큰 포함 (POST, text/plain)
      ▼
[Apps Script]  토큰 검증 → Google Sheets 읽기/쓰기 → JSON 응답
      │                    └ 사진은 Google Drive 에 저장하고 링크만 시트에 기록
      ▼
[브라우저] 화면 그리기 + localStorage 에 사본 저장 (오프라인 대비)
```

**저장할 때 일어나는 일**

1. 저장 버튼을 누르면 버튼이 잠깁니다(중복 저장 방지).
2. Apps Script 가 `LockService` 로 잠금을 걸고 시트에 씁니다.
3. 수정일 때는 내가 알고 있던 `updatedAt` 과 서버의 `updatedAt` 을 비교합니다.
   다르면 "상대방이 먼저 수정했습니다" 안내가 뜨고, 덮어쓸지 선택할 수 있습니다.
4. 저장이 끝나면 자동으로 전체 데이터를 다시 불러옵니다.
5. 저장에 실패하면 작성한 내용을 **이 기기에 임시 저장**합니다.
   (설정 ☰ → 임시 저장 에서 다시 저장할 수 있습니다)

## 4. Google Sheets 시트와 필드 구조

`setupBestOneProject()` 를 실행하면 아래 18개 시트가 자동으로 만들어집니다.
**시트 이름을 직접 만들 필요는 없습니다.**

| 시트 | 담는 내용 |
| --- | --- |
| `Settings` | 여행 기본 정보 (key / value 형태) |
| `Members` | 두 사람의 닉네임·이모지·색상 |
| `Sessions` | 로그인 토큰 |
| `Reservations` | 관광·투어·공연·경기·열차·음식점·기타 예약 |
| `Flights` | 항공 |
| `Accommodations` | 숙소 |
| `Schedules` | 날짜별 일정 |
| `ScheduleComments` | 일정별 짧은 메모 |
| `DailyRecords` | 두 사람 각자의 하루 기록 |
| `SharedRecords` | 공동 기록 |
| `Photos` | 업로드한 사진 (Drive 파일 ID + 링크) |
| `JapanesePhrases` | 일본어 표현 |
| `JapaneseWords` | 일본어 단어장 |
| `Stations` | 지하철·철도역 정보 |
| `Buses` | 버스 정보 |
| `Routes` | 저장한 이동 경로 |
| `Expenses` | 지출 |
| `ActivityLogs` | 활동 기록 (누가 무엇을 저장했는지) |

### 공통 필드

`Settings`, `Sessions`, `ActivityLogs` 를 제외한 모든 시트에는 아래 필드가 들어 있습니다.

| 필드 | 뜻 |
| --- | --- |
| `id` | 고유 ID (UUID. 행 번호를 ID 로 쓰지 않습니다) |
| `tripId` | 여행 ID |
| `createdBy` / `createdAt` | 최초 작성자 / 작성 시각 |
| `updatedBy` / `updatedAt` | 마지막 수정자 / 수정 시각 (충돌 방지에 사용) |
| `isDeleted` | 삭제 표시. `TRUE` 이면 앱에서 보이지 않습니다 (행은 남습니다) |
| `isSample` | 샘플 데이터 표시. `clearSampleData()` 로 한 번에 지울 수 있습니다 |

### 4단계 · Script Properties (스크립트 속성) 설정

여기에 **비밀번호와 주소 같은 민감한 값**을 넣습니다.
이 값들은 GitHub 에도, 브라우저에도 저장되지 않습니다.

1. Apps Script 편집기 **왼쪽 메뉴**에서 **⚙️ `프로젝트 설정`** 을 누릅니다.
2. 화면을 아래로 내리면 **`스크립트 속성`** 영역이 있습니다.
3. **`스크립트 속성 추가`** 를 누르고 아래 값을 하나씩 넣습니다.
   (하나 넣을 때마다 **`스크립트 속성 저장`** 을 누르세요)

| 속성 (이름) | 값 (내용) | 설명 |
| --- | --- | --- |
| `SPREADSHEET_ID` | 1단계에서 복사한 ID | 예: `1AbCdEfGh...` |
| `DRIVE_FOLDER_ID` | 3단계에서 복사한 ID | 예: `1XyZaBcDe...` |
| `TRIP_CODE` | `bestone` | 로그인 화면에 입력할 여행 코드. 원하는 단어로 바꿔도 됩니다 |
| `SESSION_DAYS` | `180` | 로그인 유지 기간(일). 180이면 약 6개월 동안 다시 로그인하지 않아도 됩니다 |
| `TRIP_ID` | `trip-jp-2026` | 여행 구분용 ID. 아무 값이나 괜찮습니다 |
| `GEMINI_API_KEY` | `AIza...` | **(선택)** AI 도우미용 키. 넣지 않아도 나머지 기능은 모두 동작합니다. 자세한 내용은 [5-1](#5-1-ai-도우미-사용하기) |
| `GEMINI_MODELS` | `gemini-3.5-flash-lite,gemini-3.1-flash-lite` | **(선택)** AI 모델을 쓸 순서. 비워두면 기본값을 사용합니다 |

`PASSWORD_SALT` 와 `PASSWORD_HASH` 는 **다음 순서로 만듭니다.**

#### 비밀번호 해시 만들기

1. 편집기 왼쪽 **`< >` 편집기** 아이콘을 눌러 코드 화면으로 돌아갑니다.
2. `Code.gs` 안에서 `generatePasswordHash` 를 찾습니다. (`Ctrl+F` 로 검색)
3. 이 줄을 찾습니다.

```javascript
var PASSWORD = 'PUT-YOUR-PASSWORD-HERE'; // ← 여기에 원하는 비밀번호를 입력하세요
```

4. `PUT-YOUR-PASSWORD-HERE` 부분을 **두 사람이 함께 쓸 비밀번호**로 바꿉니다.
   예) `var PASSWORD = 'ourjapan2026';`
5. 💾 저장 후, 편집기 위쪽 **함수 선택 상자**에서 **`generatePasswordHash`** 를 고릅니다.
6. **▶ 실행** 버튼을 누릅니다.
   (처음 실행하면 권한 승인 창이 뜹니다 → 아래 **[권한 승인하기]** 참고)
7. 화면 아래 **`실행 로그`** 에 이런 내용이 나옵니다.

```
PASSWORD_SALT (이미 스크립트 속성에 저장됨): a1b2c3d4e5f6g7h8
PASSWORD_HASH (아래 값을 복사해서 스크립트 속성에 붙여 넣으세요):
9f2b8c1e4d7a....(64자리 긴 문자열)....
```

8. 이 **64자리 문자열을 복사**합니다.
9. 다시 **⚙️ 프로젝트 설정 → 스크립트 속성** 으로 가서 추가합니다.

| 속성 | 값 |
| --- | --- |
| `PASSWORD_HASH` | 복사한 64자리 문자열 |

   (`PASSWORD_SALT` 는 함수 실행 때 **자동으로 저장**되므로 직접 넣지 않아도 됩니다.
   목록에 없다면 로그에 나온 값을 직접 추가하세요.)

10. **⚠️ 중요** : 코드로 돌아가 `PASSWORD` 값을 다시 `'PUT-YOUR-PASSWORD-HERE'` 로 되돌리고 저장하세요.
    비밀번호 원문이 코드에 남지 않게 하기 위함입니다.
    (GitHub 에 올리는 `Code.gs` 에도 절대 원문을 넣지 마세요)

> 정리하면, **비밀번호 원문은 어디에도 저장되지 않습니다.**
> 서버에는 `salt` 와 `SHA-256 해시`만 있고, 로그인할 때 같은 방식으로 계산해 비교합니다.

#### 권한 승인하기 (처음 실행할 때 한 번만)

1. **`권한 검토`** 버튼을 누릅니다.

   → 이것은 내가 직접 만든 개인 프로젝트라 정상입니다.
4. 왼쪽 아래 **`고급`** 을 누릅니다.
5. 맨 아래 **`BestOne API(안전하지 않음)으로 이동`** 을 누릅니다.
6. **`허용`** 을 누릅니다.

> **왜 "모든 사용자" 인가요?**
> 파트너가 자기 Google 계정으로 로그인하지 않고도 앱을 쓸 수 있게 하려면 필요합니다.
> 대신 **여행 코드 + 비밀번호 + 세션 토큰**으로 앱이 직접 접근을 막습니다.

4. **`배포`** 를 누릅니다. (처음이면 권한 승인 창이 다시 나올 수 있습니다 → 4단계와 동일하게 진행)

```
https://script.google.com/macros/s/AKfycbx.....긴문자열...../exec
```

6. 이 주소를 브라우저 새 탭에 붙여 넣고 열어 보세요. 아래처럼 나오면 성공입니다.

```json
{"success":true,"data":{"app":"BestOne in Japan API", ... },"message":"BestOne API 가 정상 동작 중입니다."}
```

#### 코드를 수정한 뒤에 다시 배포하는 방법 ★중요★

`Code.gs` 를 고치면 **반드시 새 버전으로 다시 배포해야** 반영됩니다.

1. **`배포`** → **`배포 관리`**
2. 목록에서 기존 배포 오른쪽의 **✏️ 연필 아이콘** 클릭
3. **`버전`** 을 **`새 버전`** 으로 변경
4. **`배포`** 클릭

> 이 방법으로 하면 **웹 앱 URL 이 바뀌지 않습니다.**
> `새 배포` 로 만들면 주소가 새로 생기므로 `config.js` 도 고쳐야 합니다.

### 8단계 · GitHub 파일 설정과 GitHub Pages 배포

#### 8-1. `config.js` 에 주소 넣기

`config.js` 파일을 열어 **맨 위에서 20번째 줄쯤**에 있는 이 부분을 찾습니다.

```javascript
const API_CONFIG = {
  /** ↓↓↓ 이 값을 본인의 Apps Script 웹 앱 URL 로 바꿔주세요 ↓↓↓ */
  API_URL: 'PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE',
```

`'PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE'` 를 7단계에서 복사한 주소로 바꿉니다.
**작은따옴표는 지우지 마세요.**

```javascript
  API_URL: 'https://script.google.com/macros/s/AKfycbx...../exec',
```

같은 파일 아래쪽의 `DEFAULT_TRIP_CODE` 도 4단계에서 정한 `TRIP_CODE` 와 같게 맞춥니다.

```javascript
const DEFAULT_TRIP_CODE = 'bestone';
```

사용자 이름도 원하는 대로 바꿀 수 있습니다.

```javascript
const USER_PRESETS = [
  { nickname: 'chichiboo', label: '어린왕자', emoji: '⭐' },
  { nickname: 'neederes',  label: '코끼리',   emoji: '🐘' }
];
```

#### 8-2. GitHub 에 파일 올리기

**웹에서 하는 방법 (가장 쉬움)**

1. GitHub 저장소 페이지로 갑니다.
2. `config.js` 파일을 클릭 → 오른쪽 위 **✏️ (Edit this file)** 클릭
3. 주소를 넣고 아래 **`Commit changes`** 클릭

**컴퓨터에서 하는 방법**

```bash
git clone https://github.com/사용자이름/bestonejapan.git
cd bestonejapan
# config.js 를 편집기로 열어 수정
git add .
git commit -m "Apps Script URL 설정"
git push
```

#### 8-3. GitHub Pages 켜기

이 저장소에는 `.github/workflows/deploy-pages.yml` 이 이미 들어 있어서,
**Source 를 `GitHub Actions` 로 선택**하면 push 할 때마다 자동으로 배포됩니다.
(`Deploy from a branch` 방식을 쓰고 싶다면 아래 "방법 B" 를 참고하세요)

**방법 A · GitHub Actions 로 자동 배포 (권장)**

1. 저장소 상단 메뉴에서 **`Settings`** 를 누릅니다.
2. 왼쪽 메뉴에서 **`Pages`** 를 누릅니다.
3. **`Build and deployment`** 항목에서 **Source** 를 **`GitHub Actions`** 로 선택합니다.
   (드롭다운을 열면 "GitHub Actions" 항목이 보입니다. 별도로 브랜치나 폴더를 고를 필요는 없습니다)
4. 저장소 위쪽 **`Actions`** 탭을 누릅니다.
5. **`Deploy to GitHub Pages`** 워크플로가 보이면 눌러서 오른쪽의 **`Run workflow`** 버튼으로 한 번 실행합니다.
   (이미 push 가 되어 있었다면 자동으로 한 번 실행되어 있을 수도 있습니다)
6. 초록색 체크(✅)로 완료되면, 다시 **`Settings → Pages`** 로 돌아가 주소를 확인합니다.

```
Your site is live at https://사용자이름.github.io/bestonejapan/
```

7. 스마트폰에서 이 주소를 열어 보세요.

> 이후로는 `git push` 로 코드를 올릴 때마다(또는 GitHub 웹에서 파일을 수정해 커밋할 때마다)
> **`Actions` 탭에 새 실행이 자동으로 생기고, 1~2분 뒤 사이트에 반영**됩니다.
> 따로 `Save` 버튼을 누르거나 배포 브랜치를 선택할 필요가 없습니다.

**방법 B · 브랜치에서 바로 배포 (더 단순하지만 워크플로 파일은 쓰이지 않음)**

1. **`Settings → Pages → Build and deployment`** 에서 **Source** 를 **`Deploy from a branch`** 로 선택합니다.
2. **Branch** 를 저장소의 기본 브랜치로, 폴더는 **`/ (root)`** 로 선택하고 **`Save`** 를 누릅니다.
3. 이 방법을 쓰면 `.github/workflows/deploy-pages.yml` 은 실행되지 않아도 무방합니다.
   (Actions 탭에 매번 배포 실행이 남는 게 번거롭다면 이 방법을 선택하세요)

#### 8-4. 스마트폰에 앱으로 설치하기 (PWA)

* **안드로이드(크롬)** : 주소 열기 → 오른쪽 위 `⋮` → **`앱 설치`** 또는 **`홈 화면에 추가`**
* **아이폰(사파리)** : 주소 열기 → 아래 **공유 버튼** `⬆️` → **`홈 화면에 추가`**

### 11단계 · 오류 해결

<details open>
<summary><b>Failed to fetch (서버에 연결하지 못했습니다)</b></summary>

가장 흔한 오류입니다. 아래를 순서대로 확인하세요.

1. `config.js` 의 `API_URL` 이 **`/exec`** 로 끝나나요? (`/dev` 는 안 됩니다)
2. Apps Script **`배포` → `배포 관리`** 에서 **액세스 권한이 `모든 사용자`** 인가요?
3. 웹 앱 주소를 브라우저에 직접 붙여 넣었을 때 JSON 이 나오나요?
   * 로그인 화면이 나온다면 → 액세스 권한 설정이 잘못된 것입니다.
4. 인터넷(와이파이/데이터)이 연결되어 있나요?
5. 회사·학교 네트워크에서 `script.google.com` 이 차단된 경우가 있습니다. 다른 네트워크로 시도해 보세요.
</details>

<details open>
<summary><b>CORS 오류 (No 'Access-Control-Allow-Origin' header is present)</b> ★가장 많이 발생★</summary>

브라우저 콘솔에 이런 메시지가 보이는 경우입니다.

```
Access to fetch at 'https://script.google.com/macros/s/.../exec'
from origin 'https://사용자이름.github.io' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

**원인은 앱 코드가 아니라 Apps Script 배포 설정입니다.**

웹 앱의 **"액세스 권한이 있는 사용자"** 가 `모든 사용자` 가 아니면,
Google 은 요청을 **구글 로그인 페이지로 리디렉션**합니다.
그 로그인 페이지에는 CORS 헤더가 없기 때문에 브라우저가 응답을 막고
위 메시지를 띄웁니다. (앱은 preflight 가 생기지 않는 방식으로 요청하므로
`Content-Type` 이나 헤더 문제는 아닙니다)

**해결 순서**

1. Apps Script 편집기 오른쪽 위 **`배포`** → **`배포 관리`** 를 엽니다.
2. 현재 배포 오른쪽의 **연필(✏️)** 아이콘을 누릅니다.
3. **`액세스 권한이 있는 사용자`** 를 **`모든 사용자`** 로 바꿉니다.
   → `나만`, `Google 계정이 있는 모든 사용자` 로 되어 있으면 반드시 실패합니다.
4. **`버전`** 을 **`새 버전`** 으로 바꾸고 **`배포`** 를 누릅니다.
5. 웹 앱 주소(`.../exec`)를 **브라우저 새 탭에 직접 붙여 넣어** 확인합니다.
   * `{"success":true, ...}` JSON 이 보이면 → 설정 정상
   * 구글 로그인 화면이나 "액세스 권한이 없습니다" 가 보이면 → 3번이 아직 잘못된 것

> 앱 로그인 화면에서 이 오류가 나면 **[웹 앱 주소 새 탭에서 열어보기]** 버튼이
> 자동으로 나타납니다. 그 버튼으로 5번을 바로 확인할 수 있습니다.

**그래도 안 되면**

* `config.js` 의 `API_URL` 이 `/exec` 로 끝나는지 확인하세요. (`/dev` 는 CORS 가 안 됩니다)
* `배포 관리` 에서 **활성(Active)** 상태인 배포의 주소인지 확인하세요.
  보관 처리된 배포 주소는 오류 페이지를 돌려주고, 그 페이지에도 CORS 헤더가 없습니다.
* `Code.gs` 에 문법 오류가 있으면 Google 이 HTML 오류 페이지를 돌려주어 같은 증상이 납니다.
  편집기에서 저장이 정상적으로 되는지 확인하세요.
* Apps Script 는 응답 헤더를 직접 설정할 수 없습니다.
  `setHeader` 같은 코드를 넣어 해결하려 하지 마세요.
</details>

   올라가 있는지 확인하세요. (다른 브랜치에만 있으면 Actions 가 인식하지 못합니다)
3. 워크플로는 있는데 실행 기록이 없다면, 그 워크플로를 열고 오른쪽의
   **`Run workflow`** 버튼으로 수동 실행해 보세요.
4. 실행이 **빨간 X(실패)** 로 끝났다면 그 실행을 눌러 로그를 확인하세요.
   `Get Pages site failed` 같은 메시지가 보이면 1번(Source 설정)이 원인인 경우가 대부분입니다.
5. 저장소가 **Private** 라면 GitHub Pages 는 무료 요금제에서도 동작하지만,
   조직 계정의 정책에 따라 Pages 자체가 막혀 있을 수 있습니다.
   `Settings → Pages` 화면에 안내 문구가 있는지 확인하세요.
6. 워크플로 파일의 `on: push: branches:` 에 적힌 이름이 실제 기본 브랜치 이름과
   같은지 확인하세요. 브랜치 이름을 바꿨다면 워크플로 파일도 함께 고쳐야 합니다.
</details>

<details open>
<summary><b>탑승 시각·날짜가 "1899-12-30T..." 나 "NaN" 처럼 이상하게 보임</b> ★중요★</summary>

항공 탑승 시각, 일정 시각, 체크인 날짜 등을 정확히 입력했는데
다시 보면 `1899-12-30T08:47:08Z` 같은 값이나 `8월 NaN일` 처럼 깨져 보이는 경우입니다.

**원인** : 이 문제는 데이터가 지워진 것이 아닙니다.
Google Sheets 가 `09:22`, `2026-08-05` 같은 문자열을 셀에 쓰면
사람이 직접 입력한 것처럼 **자동으로 날짜/시각 형식으로 바꿔버립니다.**
시각만 있는 값은 "1899년 12월 30일" 을 기준일로 저장하기 때문에,
다시 불러올 때 시각 부분만 필요한데 날짜까지 섞인 값이 나오는 것입니다.

**해결 방법**

1. 최신 `Code.gs` 를 Apps Script 에 붙여 넣고 저장합니다.
   (날짜/시각 컬럼을 "일반 텍스트" 서식으로 고정해 앞으로는 이 문제가 생기지 않습니다)
2. **`배포` → `배포 관리` → ✏️ → 버전 `새 버전` → `배포`** 로 다시 배포합니다.
3. Apps Script 편집기에서 함수 선택 상자에 **`repairDateTimeColumns`** 를 고르고 **▶ 실행**합니다.
   이미 깨져 있던 값을 원래 입력했던 시각/날짜로 되돌려 줍니다.
   (`setupBestOneProject()` 를 다시 실행해도 이 복구가 함께 실행됩니다)
4. 앱에서 **⟳ 새로고침** 을 눌러 정상으로 보이는지 확인합니다.

이 함수는 여러 번 실행해도 안전하며, 이미 정상인 값은 건드리지 않습니다.
실행 로그에 `[복구] Flights 시트에서 N칸을 고쳤습니다` 처럼 무엇을 고쳤는지 나옵니다.

## 5-1. AI 도우미 사용하기

화면 오른쪽 아래에 떠 있는 **✨ 버튼**을 누르면 어느 화면에서든 AI에게 물어볼 수 있습니다.
Google 의 **Gemini** 를 사용하며, 앱에 저장된 여행 정보(일정 · 항공 · 숙소 · 예약 · 경로 · 기록 · 경비)를
함께 보내주기 때문에 "**오늘 몇 시에 나가야 해?**" 같은 질문에도 우리 여행 기준으로 답합니다.
앱에 없는 내용(예: "삿포로 8월 날씨 어때?")은 **구글 검색**으로 찾아서 답합니다.

### ★ API 키는 어디에 넣나요 (가장 많이 묻는 질문)

**Apps Script 의 `스크립트 속성` 에 넣습니다.** 코드 파일에는 넣지 않습니다.

```
[내 브라우저] --(로그인 토큰만)--> [Apps Script] --(API 키)--> [Gemini]
                                     ↑
                            키는 여기에만 있습니다
```

브라우저는 키를 **아예 받지 않습니다.** 그래서 앱 주소를 아는 사람이 키를 훔쳐갈 수 없고,
로그인한 사람(= 여행 코드와 비밀번호를 아는 두 사람)만 AI를 쓸 수 있습니다.
휴대폰·PC 어디서 열어도 **한 번만 넣으면** 둘 다 바로 됩니다.

#### 1) API 키 만들기 (무료로 시작할 수 있습니다)

1. [https://aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에 접속합니다.
2. Google 계정으로 로그인합니다.
3. **`Create API key`** 를 누릅니다.
4. `AIza` 로 시작하는 긴 문자열이 나옵니다. **복사** 합니다.

#### 2) 스크립트 속성에 넣기

1. Apps Script 편집기를 엽니다. (Google Sheets → 확장 프로그램 → Apps Script)
2. 왼쪽 메뉴에서 **⚙️ `프로젝트 설정`** 을 누릅니다.
3. 아래로 내려 **`스크립트 속성`** → **`스크립트 속성 추가`** 를 누릅니다.
4. 아래와 같이 넣고 **`스크립트 속성 저장`** 을 누릅니다.

| 속성 (이름) | 값 (내용) |
| --- | --- |
| `GEMINI_API_KEY` | 복사한 `AIza...` 키 |

5. **⚠️ 다시 배포해야 적용됩니다.**
   편집기 오른쪽 위 **`배포` → `배포 관리`** → 연필(✏️) 아이콘 → **버전: `새 버전`** → **`배포`**
   *(배포 주소는 바뀌지 않으므로 `config.js` 는 고칠 필요가 없습니다)*
6. 앱을 새로고침하고 ✨ 버튼 → ⚙ 를 눌러
   **"서버에 안전하게 보관 중"** 이라고 나오면 성공입니다.
   아직 "서버에 키가 없습니다" 라면 **`서버 상태 다시 확인`** 을 눌러보세요.

> **잘 됐는지 확인하는 법**
> Apps Script 편집기에서 **`checkSetup`** 함수를 실행하면 실행 로그에
> `[OK] GEMINI_API_KEY = AIzaSyAb...(생략)` 이 보입니다.
> (`setupBestOneProject` 을 실행해도 같은 내용을 알려줍니다)

#### 3) (예비) 서버에 넣기 전에 급하게 써보고 싶다면

앱의 ✨ 버튼 → ⚙ → **`이 기기에 개인 키 따로 넣기`** 에 키를 붙여 넣으면
그 브라우저에서만 임시로 쓸 수 있습니다. 이때는 브라우저가 Gemini 를 직접 부릅니다.
**기기마다 따로 넣어야 하고**, 서버에 키를 넣으면 자동으로 서버 방식이 우선합니다.

#### ⚠️ GitHub 환경변수(Secrets)는 왜 안 쓰나요

GitHub Pages 는 **정적 사이트**라서 서버에서 값을 숨겨줄 방법이 없습니다.
GitHub Actions Secret 에 키를 넣고 빌드할 때 파일에 심으면,
그 값이 **배포된 자바스크립트 안에 그대로 들어가** 누구나 브라우저 개발자도구로 볼 수 있습니다.
저장소를 비공개로 해도 배포된 페이지는 공개이므로 마찬가지입니다.

그래서 이 앱은 **이미 갖고 있는 서버(Apps Script)** 에 키를 두는 방식을 씁니다.
Actions Secret 은 키가 아니라 "숨길 필요 없는 설정값"에만 쓰는 것이 맞습니다.

> **키를 더 안전하게 하는 요령**
> AI Studio 의 키 상세 화면에서 **API 제한**을 `Generative Language API` 하나로 좁혀두면,
> 혹시 키가 새어 나가도 다른 서비스에는 쓸 수 없습니다.
> 키를 바꾸고 싶으면 스크립트 속성의 값만 새 키로 바꾸고 다시 배포하면 됩니다.

### 어떤 모델을 쓰고 있는지 (배터리 모양 표시)

채팅창 위쪽에 **배터리처럼 생긴 막대**가 있습니다.
칸의 개수는 내 모델 목록의 개수와 같고, **몇 번째 모델까지 내려왔는지**를 채워서 보여줍니다.

| 모양 | 뜻 |
| --- | --- |
| 초록 칸 1개 | 1순위 모델로 잘 답하고 있음 (가장 좋은 상태) |
| 노란 칸 2~ | 앞 모델이 막혀서 중간 순위 모델로 넘어감 |
| 빨간 칸이 끝까지 | 마지막 순위 모델까지 내려옴 (사용량이 거의 찼을 수 있음) |
| 전부 비어 있고 `대기 중` | 아직 한 번도 답하지 않음 (또는 키 없음) |

막대 옆에는 지금 답하고 있는 **모델 이름**이 짧게 표시됩니다. (예: `3.5-flash`)
막대 위에 마우스를 올리면 `지금 모델: … (3번째 / 전체 5개)` 처럼 자세히 나옵니다.

### 모델 이름이 바뀌었을 때 (구글이 자주 바꿉니다)

쓸 모델의 순서는 세 곳에서 정해지고, **위에 있는 것이 먼저** 적용됩니다.

| 순위 | 정하는 곳 | 바꾸는 방법 |
| --- | --- | --- |
| 1 | 앱에서 내가 고른 순서 | ✨ → ⚙ → `모델 순서` 에서 `↑`/`✕` 로 편집 (이 브라우저에만 저장) |
| 2 | 스크립트 속성 `GEMINI_MODELS` | 쉼표로 구분해 적기 — 두 사람 모두에게 적용됩니다 |
| 3 | `config.js` 의 `AI_CONFIG.MODELS` | 위 두 곳이 비어 있을 때 쓰는 기본값 |

기본값은 이렇습니다.

```javascript
MODELS: [
  'gemini-flash-lite-latest',  // 이름이 바뀌어도 계속 동작
  'gemini-flash-latest',
  'gemini-2.5-flash',
  'gemini-2.0-flash-lite',
  'gemini-2.0-flash',
  // ↓ 아직 없는 이름. 나중에 생기면 자동으로 먼저 쓰입니다
  'gemini-3.5-flash-lite',
  'gemini-3.1-flash-lite'
]
```

앞의 모델이 **없거나(404) 사용량이 꽉 차면(429 · 503)** 자동으로 다음 모델로 넘어갑니다.

**앱은 먼저 "지금 이 키로 실제 쓸 수 있는 모델 목록"을 확인합니다.**
그래서 없는 이름은 두드려 보지도 않습니다. 미리 적어두어도 손해가 없고,
나중에 그 이름이 생기면 자동으로 먼저 쓰이게 됩니다.

기본 목록의 앞 두 개는 **`-latest`** 로 끝납니다. 이 이름은 구글이 모델 이름을
바꿔도 그대로 남기 때문에, 이름 변경에 가장 안전한 방법입니다.

적어둔 이름이 전부 없으면 실제 목록에서 가장 알맞은 것으로 바꿔 답하고
("… 대신 ○○ 로 답했습니다" 안내가 뜹니다).

그래도 안 되면 **코드를 고치지 않고** 이렇게 직접 고를 수 있습니다.

1. `AI 도우미 설정` 화면을 엽니다.
2. **`사용 가능한 모델 불러오기`** 를 누릅니다.
   → 내 키로 **실제로 쓸 수 있는** 모델 이름이 알약 모양으로 나옵니다.
3. 쓰고 싶은 이름을 누르면 목록 맨 아래에 추가됩니다.
4. `↑` 버튼으로 순서를 올리고, `✕` 로 안 쓰는 모델을 뺍니다.
5. 되돌리고 싶으면 **`기본값으로`** 를 누르세요.

두 사람 모두에게 한 번에 적용하고 싶다면, 확인한 이름을 스크립트 속성
`GEMINI_MODELS` 에 `gemini-3.5-flash-lite,gemini-2.5-flash-lite` 처럼 쉼표로 적고
다시 배포하세요.

### AI 도우미 관련 오류 해결

| 증상 | 원인과 해결 |
| --- | --- |
| ✨ 버튼을 눌러도 설정 화면만 뜸 | 아직 키가 없습니다. 위 **2) 스크립트 속성에 넣기** 를 진행하세요 |
| 키를 넣었는데 계속 "서버에 키가 없습니다" | **다시 배포**를 안 했을 가능성이 큽니다. `배포 → 배포 관리 → ✏️ → 새 버전 → 배포` 후 `서버 상태 다시 확인` 을 누르세요 |
| `GEMINI_API_KEY 가 올바르지 않습니다` | 키를 복사할 때 앞뒤 공백이나 줄바꿈이 섞였을 수 있습니다. 스크립트 속성의 값을 지우고 다시 붙여 넣은 뒤 재배포하세요 |
| `모든 모델을 시도했지만 실패했습니다` | 모델 이름이 바뀌었을 가능성이 큽니다. 위 **모델 이름이 바뀌었을 때** 를 따라 하세요 |
| 답변 말풍선이 **비어 있음** | 예전 버전의 문제입니다. 새 `script.js` 가 올라가면 이유가 글로 표시됩니다. 홈 화면 앱이라면 삭제 후 다시 설치하세요 |
| `알 수 없는 요청입니다: aiChat` | Apps Script 가 예전 버전입니다. 새 `Code.gs` 를 붙여넣고 다시 배포해 주세요 |
| `적어둔 모델 이름을 하나도 찾을 수 없습니다` | 앱이 자동으로 실제 모델을 찾아 다시 시도하지만, 그마저 실패한 경우입니다. 안내에 나온 이름 중 하나를 `GEMINI_MODELS` 에 넣어주세요 |
| **`무료 사용량이 0으로 잡혀 있습니다`** | 키를 만든 Google Cloud 프로젝트가 무료 사용량 대상이 아닙니다. **모델을 바꿔도 소용없습니다.** [aistudio.google.com/apikey](https://aistudio.google.com/apikey) → `Create API key` → **`Create API key in new project`(새 프로젝트)** 로 키를 새로 만들어 `GEMINI_API_KEY` 를 바꾸고 다시 배포하세요 |
| `사용량이 잠시 가득 찼습니다` | 분당 한도에 걸린 것입니다. 앱이 잠깐 기다렸다 다시 시도하고, 안 되면 다음 모델로 넘어갑니다. 잠시 뒤 다시 물어보세요 |
| `이제 새로 쓸 수 없는 모델입니다` | 구글이 그 모델을 닫았습니다. 앱이 기억해 두고 6시간 동안 다시 두드리지 않습니다. 자동으로 다른 모델을 씁니다 |
| 답이 옛날 일정 기준으로 나옴 | 오른쪽 위 `⟳` 로 자료를 새로 받은 뒤 다시 물어보세요 |
| 오프라인에서 답이 안 나옴 | AI 는 인터넷이 있어야 동작합니다. (앱의 다른 기능은 오프라인에서도 열람 가능) |
| 답변이 오래 걸림 | Apps Script 를 한 번 거치므로 몇 초 더 걸릴 수 있습니다. 급할 때는 개인 키 방식이 조금 빠릅니다 |
| PC에서는 되는데 휴대폰에서 안 됨 | **개인 키** 방식을 쓰고 있다면 키가 기기마다 따로 저장됩니다. 스크립트 속성에 넣으면 이런 일이 없습니다 |

> **AI 답변을 그대로 믿지 마세요.**
> 열차 시각 · 영업시간 · 요금처럼 틀리면 곤란한 정보는 반드시 공식 사이트에서 다시 확인하세요.
> 대화 내용은 Apps Script 를 거쳐 Google 의 Gemini 서버로 전송됩니다.
> 주민등록번호 · 카드번호 같은 민감한 정보는 입력하지 마세요.
> (대화 내용은 시트에 저장되지 않고, 최근 대화만 내 브라우저에 남습니다)

## 6. 테스트 방법

아래 순서대로 확인하면 모든 핵심 기능을 점검할 수 있습니다.
두 대의 기기(또는 브라우저 2개 - 하나는 시크릿 창)로 진행하세요.

| # | 테스트 | 방법 | 기대 결과 |
| --- | --- | --- | --- |
| 1 | **사용자 1 로그인** | 기기 A에서 `어린왕자` 선택 후 로그인 | 오늘 화면이 뜨고 오른쪽 위에 닉네임 표시 |
| 2 | **사용자 2 로그인** | 기기 B에서 `코끼리` 선택 후 로그인 | 같은 여행 데이터가 보임 |
| 3 | **사용자 1이 일정 추가** | 기기 A → 일정 탭 → `＋ 일정 추가` → 저장 | "저장되었습니다" 토스트 |
| 4 | **사용자 2가 확인** | 기기 B → 오른쪽 위 `⟳` | 새 일정이 보이고 작성자 배지가 파란색(상대방) |
| 5 | **사용자 2가 기록 작성** | 기기 B → 기록 탭 → `기록 쓰기` → 저장 | 저장 후 기록 카드가 통합 피드에 나타남 |
| 6 | **사용자 1이 기록 확인** | 기기 A → 기록 탭 → 같은 날짜 | 두 사람의 기록이 작성자 표시와 함께 한 피드에 보임 |
| 7 | **사진 업로드** | 기록 탭 → 사진 → `업로드` → 사진 여러 장 선택 | 진행 막대 후 미리보기 표시. Drive 폴더에도 파일 생성 |
| 7-1 | **영상 업로드** | 같은 화면에서 짧은 영상(10MB 안팎) 선택 | `영상 올리는 중… %` 진행률이 오르고, 목록에 ▶ 표시가 붙은 칸이 생김 |

## 7. 자주 발생하는 오류 해결

위 [11단계](#11단계--오류-해결) 를 참고하세요. 그 밖의 상황은 아래와 같습니다.

| 증상 | 원인과 해결 |
| --- | --- |
| 저장은 되는데 화면에 안 보임 | `isDeleted` 가 `TRUE` 인지 시트에서 확인. `⟳` 새로고침 |
| 날짜가 하루 밀려 보임 | 앱은 **Asia/Tokyo** 기준으로 계산합니다. 한국에서 접속해도 동일합니다. 시트에 직접 입력할 때는 `2026-04-20` 형식(문자)으로 넣으세요 |
| 시트에 직접 입력했는데 앱에 안 나옴 | `id` 칸이 비어 있으면 안 됩니다. 아무 고유 문자열이나 넣으세요. `isDeleted` 는 비우거나 `FALSE` |
| "다른 저장이 진행 중입니다" | 두 사람이 동시에 저장할 때 잠깐 나옵니다. 잠시 후 다시 시도 |
| Apps Script 실행 시간 초과 | 데이터가 아주 많을 때. `ActivityLogs` 시트의 오래된 행을 지우면 빨라집니다 |
| 날씨가 "불러오지 못했습니다" 로 나옴 | 인터넷 연결을 확인하세요. 날씨는 [Open-Meteo](https://open-meteo.com) 를 쓰며 API 키가 필요 없습니다. 회사·학교 네트워크에서 막혀 있을 수 있습니다 |
| 다른 도시 날씨를 보고 싶음 | `config.js` 의 `COUNTRY_CONFIG.weatherCities` 에 이름과 위도 · 경도를 넣으면 됩니다 |
| 일본어 음성이 안 나옴 | 기기에 일본어 음성이 없을 수 있습니다. (안드로이드: 설정 → 언어 → 텍스트 음성 변환에서 일본어 설치) |
| 사진이 깨져 보임 | Drive 파일 공유 설정이 "링크가 있는 사용자"인지 확인 (3단계 주의사항) |
| 영상 칸이 회색으로만 보임 | Drive 가 미리보기 그림을 만드는 데 몇 분 걸립니다. ▶ 를 눌러 재생하는 것은 바로 됩니다 |
| 영상 업로드가 중간에 멈춤 | 조각마다 두 번까지 자동으로 다시 시도합니다. 그래도 실패하면 신호가 좋은 곳에서 다시 올려주세요. 남은 조각은 Apps Script 에서 `cleanupStaleUploads` 를 실행하면 정리됩니다 |
| `알 수 없는 요청입니다: uploadChunk` | Apps Script 가 예전 버전입니다. 새 `Code.gs` 로 다시 배포해 주세요 |
| 영상을 더 크게 올리고 싶음 | 스크립트 속성에 `VIDEO_MAX_MB` 를 추가하면 최대 60까지 올릴 수 있습니다. 다만 클 수록 실패 확률이 높아집니다 |
| 시각이 `1899-12-30…` 으로 바뀜 | 예전 버전에서 Google Sheets 가 `09:22` 를 시각 서식으로 바꿔 생긴 값입니다. Apps Script 편집기에서 **`repairDateTimeColumns`** 함수를 한 번 실행하면 날짜 · 시각 칸이 모두 문자 서식으로 고정되고 값이 복구됩니다 |
| 시트에 시각을 직접 넣으면 또 깨짐 | 셀을 선택하고 **서식 → 숫자 → 일반 텍스트** 로 바꾼 뒤 `09:22` 형식으로 입력하세요 |
| 붙여넣기(`Ctrl+V`)가 안 됨 | ① 첨부 영역을 **한 번 클릭**해서 선택한 뒤 붙여 넣으세요. ② 브라우저가 클립보드 권한을 물어보면 **허용**을 누르세요. ③ Safari 는 `클립보드에서 붙여넣기` 버튼을 눌러야 할 수 있습니다 |
| PDF 팝업이 검게 나오거나 문서가 잘려 보임 | 예전 버전은 Drive 미리보기 화면을 그대로 가져다 썼는데, 브라우저가 서드파티 쿠키를 막으면 Drive 가 자기 로그인 화면을 열려다 스스로 차단해 이렇게 됩니다. 지금은 앱이 **파일 내용만 받아와 브라우저 내장 PDF 뷰어로** 엽니다. 새 `Code.gs` 를 붙여넣고 **다시 배포**하면 해결됩니다 |
| PDF 팝업 아래에 "앱 안에서 바로 열지 못했습니다" 가 뜸 | Apps Script 가 예전 버전입니다(`getFileData` 기능이 없음). 새 `Code.gs` 로 다시 배포해 주세요. 그 전까지는 `새 탭에서 열기` 를 쓰시면 됩니다 |
| PDF 가 "파일이 너무 큽니다" | 18MB 가 넘는 파일은 앱 안에서 열지 않습니다. `새 탭에서 열기` 를 사용하세요 |
| ✨ AI 버튼이 안 보임 | 로그인 후에만 보입니다. 그래도 없으면 브라우저를 완전히 껐다 켜서 새 버전을 받으세요 (자세한 내용은 [5-1](#5-1-ai-도우미-사용하기)) |

## 8. 다른 나라 버전으로 바꾸는 방법

국가 정보가 코드 전체에 흩어져 있지 않고 **`config.js` 한 곳**에 모여 있습니다.

### 8-1. 프런트엔드 (`config.js`)

```javascript
const COUNTRY_CONFIG = {
  code: 'FR',
  nameKo: '프랑스',
  nameEn: 'France',
  currency: 'EUR',
  currencySymbol: '€',
  timezone: 'Europe/Paris',
  language: 'fr',
  speechLang: 'fr-FR',
  appName: 'BestOne in France',
  subtitle: '«어린왕자와 코끼리의 프랑스 여행»',
  localLabels: {
    phrases: '회화',
    words: '주요 어휘',
    transit: '노선 · 길찾기',
    routes: '이동 경로'
  },
  emergency: [
    { label: '통합 긴급전화', value: '112' },
    { label: '주프랑스 대한민국 대사관', value: '+33-1-4753-0101' }
  ],
  externalLinks: [
    { label: 'Google 지도', url: 'https://www.google.com/maps' },
    { label: 'SNCF Connect', url: 'https://www.sncf-connect.com/' }
  ]
};
```

`API_CONFIG.STORAGE_PREFIX` 도 함께 바꾸면 (`bestone_fr_`) 나라별 데이터가 섞이지 않습니다.

> **노선 · 길찾기 탭은 현재 일본(도쿄·삿포로) 전용 데이터입니다.**
> `data/transit.js` 를 그 나라의 노선 자료로 새로 만들기 전까지는
> 다른 나라 버전에서 이 탭이 빈 화면으로 보입니다.
> (자료를 만드는 방법은 `data/build_transit.py` 파일 첫머리 주석을 참고하세요)

### 8-2. 시간대 처리 (`script.js`)

`script.js` 위쪽의 이 상수를 바꾸세요.

```javascript
const TZ_OFFSET_HOURS = 9;   // Asia/Tokyo
```

| 나라 | 값 |
| --- | --- |
| 일본 | `9` |
| 태국 | `7` |
| 영국 | `0` (여름 서머타임 기간에는 `1`) |
| 프랑스 | `1` (여름 서머타임 기간에는 `2`) |

### 8-3. 백엔드 (`Code.gs`)

1. **새 스프레드시트**와 **새 Apps Script 프로젝트**를 만드세요. (나라별로 분리하는 편이 안전합니다)
2. `Code.gs` 안의 아래 부분을 바꿉니다.

```javascript
function todayJst_() {
  return Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyy-MM-dd');   // ← 시간대 변경
}
```

`readSheetObjects_` 안의 `'Asia/Tokyo'` 도 같은 값으로 바꾸면 됩니다.

3. `SEED_PHRASES_()` 와 `SEED_WORDS_()` 의 내용을 그 나라 언어로 교체합니다.
   형식만 유지하면 됩니다.
   * 표현 : `['카테고리', '한국어', '현지어', '한국어식 읽는 법']`
   * 단어 : `['카테고리', '현지어', '읽는 법', '한국어']`
   * 카테고리 키는 `config.js` 의 `PHRASE_CATEGORIES` / `WORD_CATEGORIES` 와 같아야 합니다.
     (현재 표현 카테고리: `greeting`, `airport`, `train`, `bus`, `taxi`, `hotel`,
     `restaurant`, `shopping`, `sightseeing`, `venue`, `emergency`)
4. `setupBestOneProject()` 안의 기본값(`country`, `city`, `currency`, `timezone`, `emergencyContact`)을 바꿉니다.

### 8-4. 화면 문구

`index.html` 의 아래 부분은 `config.js` 값으로 자동 교체되지만, 초기 표시값도 바꿔두면 깔끔합니다.

```html
<span id="brandCountry">Japan</span>
<span class="brand-sub" id="brandSubtitle">«어린왕자와 코끼리의 일본 여행»</span>
```

시트 구조와 API 는 나라와 관계없이 **그대로 사용**할 수 있습니다.

## 9. 개인정보 · 보안 주의사항

* 이 앱은 **공개 서비스가 아니라 두 사람이 쓰는 개인 앱**입니다. 회원가입 기능은 없습니다.
* **비밀번호 원문은 어디에도 저장되지 않습니다.** (salt + SHA-256 해시만 서버에 보관)
* **프런트엔드 코드(`config.js`, `script.js`)에는 비밀번호도 API 키도 없습니다.** GitHub 에 공개해도 됩니다.
* **Gemini API 키도 서버(스크립트 속성)에만 있습니다.** 브라우저로 내려오지 않으므로
  앱 주소를 아는 사람이 내 키를 가져다 쓸 수 없습니다.
  (GitHub Actions Secret 에 넣는 방식은 **쓰지 않습니다** — 정적 사이트라 배포본에 그대로 노출됩니다.
  자세한 이유는 [5-1](#5-1-ai-도우미-사용하기))
* Apps Script 웹 앱 주소만으로는 데이터를 읽거나 고칠 수 없습니다.
  모든 요청에 **세션 토큰**이 필요하고, 서버에서 검증합니다.
* 다만 이 앱은 **금융·의료 수준의 보안 체계는 아닙니다.**
  * 여권 번호, 신용카드 번호, 주민등록번호는 **입력하지 마세요.**
  * 여권 사진, 신분증 사진은 **올리지 마세요.**
  * 항공권 QR 은 좌석 확인용으로만 쓰고, 여행이 끝나면 삭제하시길 권합니다.
* Drive 에 올린 사진과 영상은 **링크를 아는 사람이 볼 수 있는 상태**가 됩니다. ([3단계 주의사항](#3단계--drive-폴더-만들기-사진-저장소))
  * 특히 영상은 주변 사람의 얼굴이나 목소리가 담기기 쉽습니다. 올리기 전에 한 번 확인해 주세요.
* 여행이 끝나면
  1. Apps Script → `배포 관리` → 배포를 **보관 처리(Archive)** 하거나
  2. `TRIP_CODE` / `PASSWORD_HASH` 를 바꿔 두시면 더 안전합니다.
  3. AI 를 더 쓰지 않는다면 스크립트 속성의 `GEMINI_API_KEY` 를 지우거나
     AI Studio 에서 키를 삭제하세요.

## 일본어 표현 데이터에 대해

기본으로 들어 있는 일본어 표현 152개와 단어 88개는 여행지에서 흔히 쓰이는
**일반적인 관용 문장**을 이 프로젝트에서 직접 정리한 것입니다.
문장 선정에 시중의 여행 회화 자료를 참고했으나, 특정 자료의 목록·해설·구성을
그대로 옮기지 않았습니다. 표기는 히라가나 전용이 아니라 실제 표지판·메뉴에서 보게 되는
**일반적인 일본어 표기(한자 + 가나)** 를 사용했습니다.

저작권이 있는 교재·PDF의 내용을 이 저장소에 그대로 옮겨 담지 마세요.
개인적으로 참고한 표현을 쓰고 싶다면 앱 안에서 **＋ 표현 추가** 로 직접 넣으면
본인 Google Sheets 에만 저장되고 공개되지 않습니다.
